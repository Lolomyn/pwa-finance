# Мои Расходы

## Что это

«Мои Расходы» — личный офлайн-трекер трат в виде PWA. Приложение работает без сервера, регистрации и внешних API, а данные хранятся только локально в IndexedDB на устройстве. После первой загрузки приложение кэшируется service worker и открывается без интернета. Его можно установить на главный экран Android и запускать в отдельном окне без адресной строки.

В приложении есть добавление и удаление трат, общий итог, статистика по периодам, график, фильтр списка по категории, а также экспорт и импорт резервной копии.

## Локальный запуск

В папке с проектом выполните:

```bash
npx serve
```

Откройте адрес из вывода команды (обычно `http://localhost:3000`).

Service worker работает только на HTTPS или на `localhost`. Поэтому открывать `index.html` напрямую через `file://` нельзя: при таком запуске PWA и офлайн-режим работать не будут.

## Деплой на GitHub Pages

1. Создайте новый репозиторий на GitHub.
2. Загрузите в корень репозитория файлы проекта: `index.html`, `styles.css`, `app.js`, `manifest.json`, `sw.js`, `README.md` и папку `icons`.
3. Откройте в репозитории **Settings → Pages**.
4. В разделе **Build and deployment** выберите источник **Deploy from a branch**, ветку `main` и папку `/root`.
5. Сохраните настройки и откройте опубликованный адрес вида `https://username.github.io/repository-name/`.

Все пути в проекте относительные, поэтому приложение корректно работает из подпапки GitHub Pages. Первый запуск должен произойти по HTTPS, чтобы service worker зарегистрировался.

## Установка на Android

1. Откройте опубликованное приложение в Chrome на Android.
2. Подождите несколько секунд после первой загрузки, чтобы service worker завершил установку.
3. Нажмите меню Chrome (три точки) и выберите **«Установить приложение»** или **«Добавить на главный экран»**.
4. Подтвердите установку. Приложение запустится в standalone-режиме без адресной строки.

Если пункт установки не появился сразу, обновите страницу и проверьте, что сайт открыт по HTTPS, а приложение уже загружалось хотя бы один раз.

## Как работает статистика

- **«Неделя»** — последние 7 дней, включая сегодня.
- **«Месяц»** — последние 30 дней, включая сегодня.
- **«Год»** — последние 365 дней, включая сегодня.
- **«Всё»** — от самой ранней траты до сегодняшнего дня.

Периоды считаются по полю `date` — дате самой траты, которую вы указали в форме. Поле `createdAt` (момент сохранения записи) на статистику не влияет. Поэтому трата, добавленная сегодня за прошлый месяц, попадёт именно в прошлый месяц.

«Итого за период», «Средний расход в день», разбивка по категориям и график пересчитываются при смене периода, добавлении и удалении трат. Средний расход — это итог за период, разделённый на количество календарных дней периода.

Фильтр списка по категории влияет только на список трат. Общий итог, статистика и график всегда считаются по всем данным.

## Резервная копия

Раздел **«Резервная копия»** позволяет сохранить данные на устройство и восстановить их.

- **«Экспорт в JSON»** скачивает файл `expenses-backup-ГГГГ-ММ-ДД.json` со всеми записями и всеми полями. Этот файл подходит для полного восстановления данных.
- **«Экспорт в CSV»** скачивает файл `expenses-ГГГГ-ММ-ДД.csv` с колонками `date,amount,category,note`. Файл отсортирован по дате, содержит BOM для корректной кириллицы в Excel и подходит для просмотра или обработки в таблицах. Для восстановления приложения используйте JSON, а не CSV.
- **«Импорт из JSON»** читает резервную копию и **заменяет все текущие данные**. Перед заменой приложение показывает подтверждение. Импорт не объединяет записи: старые траты удаляются, остаются только записи из файла.

Перед импортом проверяется, что файл содержит массив записей с корректными полями `amount`, `category` и `date`. Если файл повреждён или не проходит проверку, приложение показывает сообщение об ошибке и не меняет текущие данные. Пустой массив `[]` считается корректным: после подтверждения он очистит все траты.

Перед импортом рекомендуется сделать экспорт текущих данных: операцию замены нельзя отменить.

## Обновление приложения

После изменений в `index.html`, `styles.css`, `app.js`, `manifest.json` или иконке обязательно измените версию кэша в `sw.js`:

```js
const CACHE_NAME = 'expense-tracker-v4';
```

При следующем запуске новая версия service worker установится, заберёт обновлённые файлы в новый кэш, а старый кэш будет удалён. Без изменения имени кэша устройство может продолжать показывать старые файлы из офлайн-кэша. После публикации обновления может потребоваться одна-две перезагрузки, чтобы новый service worker активировался.

## Замена иконки

Основная иконка — локальный файл `icons/icon.svg`. Если Chrome при установке потребует растровые иконки, добавьте в папку `icons` файлы `icon-192.png` (192×192) и `icon-512.png` (512×512) и укажите их в массиве `icons` файла `manifest.json`:

```json
{
  "src": "icons/icon-192.png",
  "sizes": "192x192",
  "type": "image/png",
  "purpose": "any"
},
{
  "src": "icons/icon-512.png",
  "sizes": "512x512",
  "type": "image/png",
  "purpose": "any"
}
```

После замены иконки и правки manifest не забудьте увеличить версию кэша в `sw.js`.

## Предупреждение

Все данные хранятся только в IndexedDB в браузере на этом устройстве. Серверной копии и автоматической резервной копии нет. Очистка данных сайта в настройках браузера (в Chrome — «Данные сайтов» / «Очистить историю» с включённым пунктом данных сайтов), удаление приложения с очисткой данных или переустановка браузера могут безвозвратно удалить все траты.

Перед сменой телефона, переустановкой браузера или очисткой данных обязательно сделайте **«Экспорт в JSON»** и сохраните файл в надёжном месте. После этого данные можно восстановить через **«Импорт из JSON»** на новом устройстве.
